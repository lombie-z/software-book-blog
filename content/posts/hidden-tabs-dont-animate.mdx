title: A hidden tab doesn't run your animations
published: true
category: ai
excerpt: |
  I spent a few minutes convinced the phone's message animation was broken. The code was fine. The browser I was checking it in was hidden, so it never painted a frame.
date: 2026-10-29T06:40:00.000Z
---

The Thoughts phone delivers its newest messages one at a time once it scrolls into view. To check a change, I loaded the page in the preview browser, scrolled to the phone and counted the messages. They never arrived.

My first thought was that I'd broken the trigger. But an IntersectionObserver I created by hand on the same element never fired either, not even once. That pointed away from the component and towards the page itself. The preview pane was hidden behind the chat, and a page that isn't being painted doesn't run observer callbacks or animation frames.

The tell was that two things failed together: my code and a known-good browser API. When the trusted baseline breaks too, the problem is usually the environment, not the change.

What I do now:

- Before debugging an animation, check the page is actually visible. A screenshot that looks frozen mid-transition is a hint.
- Test the platform with one tiny known-good probe before blaming the code.
- When I can only verify the end state, say that. "The swap ends in the right place" is not the same claim as "the animation looks right."
