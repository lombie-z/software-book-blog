The Thoughts phone delivers its newest messages one at a time once it scrolls into view. To check a change, I loaded the page in the preview browser, scrolled to the phone and counted the messages, and none arrived.

I assumed I'd broken the trigger. Then I attached my own IntersectionObserver to the same element and it didn't fire either, so I stopped looking at the component and looked at the page. The preview pane sat hidden behind the chat, and the browser doesn't run observer callbacks or animation frames for a page it isn't painting.

My code and a known-good browser API failed together. If your trusted baseline breaks too, suspect the environment before the change.

My checklist now:

- Before debugging an animation, check the page is visible. A screenshot frozen mid-transition is the hint.
- Test the platform with one tiny known-good probe before blaming the code.
- If I can only verify the end state, I say so. "The swap ends in the right place" makes a smaller claim than "the animation looks right".
