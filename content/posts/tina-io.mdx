I work at [SSW](https://www.ssw.com.au), which builds TinaCMS, and I spend a lot of my week on tina.io. We build the site with Tina, so we hit the editor's rough edges before customers do and fix them in the product.

## The homepage

Each page on tina.io is a stack of blocks that the marketing team can edit and rearrange without a developer. I've built a fair few of them, including the comparison box and the markdown block below, and I audited the page titles across the site.

## AI search readiness

I built [tina.io/geo](https://tina.io/geo), a free checker. You paste in a URL and get a graded report on how ready the page is for search engines and AI answer engines, from whether AI crawlers can reach it to whether it serves markdown to agents. The tool has its own repo and Vercel project, and tina.io proxies it under `/geo`, the same way it serves TinaDocs.

## TinaDocs

[TinaDocs](https://tina.io/tinadocs) is a docs starter built on Tina. Clone it and you can edit the pages in the visual editor with no setup. I built many of the components you write docs with, like tabbed code blocks, recipe blocks and type definitions, along with the theme selector and dark mode.

<AnnotatedImage src="/uploads/posts/tina-io-recipe.webp" alt="A TinaDocs page showing a recipe block, a numbered list of steps beside a block of React code" caption="A recipe block in the TinaDocs starter." aspect="16/10" notes={[{ text: "each step lights up its lines", x: 37, y: 37.5, mark: "circle", side: "bottom", size: 18 }]} />

Search runs on Pagefind, which needs no server. Pagefind builds its index at build time, so I added a check that warns you when the dev server starts if the index has gone stale.
